- **Future dates sort as the newest items.** `fetchAllFeeds` sorts with `tb - ta` before the global per-source cap of 6, and `groupStories` uses the same descending timestamp order, so a later `publishedAt` becomes the survivor and the cluster lead. `ageHours` in `scripts/lib/score.ts` does `Math.max(0, now - t)`, so a future item has age 0 and `recencyScore` 100, and it passes every hard window (`ageH > hardDays` is false). This build shows both: the NIST symposium (`2026-09-24T13:00:00Z`, raw `Thu, 24 Sep 2026 09:00:00 -0400`) is the first Safety row, and Dark Reading “[Virtual Event] Cybersecurity Outlook 2027” (`2026-12-03T16:00:00Z`) is in the Cyber Threats preview, about 73 days ahead. `check-data.ts` pushes that negative age into the median and only `Math.max`es `maxItemAgeDays`, so the 30-day fail cannot see it. Drop a `publishedAt` after now, or age it past the hard window. Writing it back as “now” still sorts it first.
- **Exact-title dedup removes the second outlet before trending can count it.** In `fetchAllFeeds` the filter key is `title.toLowerCase()` with no source, the walk order is `SOURCES` order, and the priority sort runs after the drop. A second feed with the same headline is discarded, then `buildCategories` only trends clusters with `sources.size >= 2`. Identical headlines from a publisher and a wire never become a trending row; the Gemini and Muse clusters survived because the titles differ. Dedup URL-or-title per source, and leave cross-source title twins for the router.
